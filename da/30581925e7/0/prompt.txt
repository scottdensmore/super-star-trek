if [ -n "${CI:-}" ] &amp;&amp; [ "$(uname -s)" = Linux ]; then

### F2. The self-check can be bypassed, and the script then reports `workflow OK` over zero scripts (blocking)

This is precisely the failure mode the count comparison at `tests/workflow.sh:95-108` exists to prevent.

Mechanism: `n` is never initialised in the awk program, so `END { print n }` emits the **empty string** — not `0` — when nothing is extracted. Then:

- line 101 `if [ "$extracted" -ne "$declared" ]` → `[: Illegal number:` , exit status 2, which `if` reads as *false*, so the mismatch branch is skipped;
- line 105 `[ "$declared" -eq 0 ]` is false whenever grep found something;
- line 111 `while [ "$i" -lt "$extracted" ]` → status 2 → loop body never runs;
- `fails` is 0 → `echo "workflow OK"`, exit 0.

The `[: Illegal number:` lines go to stderr, which `ctest` hides on a pass.

Trigger (a) — **valid, ordinary YAML**, no broken tooling required. A workflow file whose only `run:` is the standard `defaults` mapping key:

```yaml
name: A
defaults:
  run:
    shell: bash
jobs:
  j:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
```
```
./tests/workflow.sh: 101: [: Illegal number: 
./tests/workflow.sh: 111: [: Illegal number: 
workflow OK
rc=0
```

Trigger (b) — a broken or missing `awk`. The extractor's exit status is never checked and `set -e` is not on:

```
$ PATH=&lt;awk-that-exits-2&gt;:$PATH ./tests/workflow.sh .
awk: simulated failure
./tests/workflow.sh: 101: [: Illegal number: 
./tests/workflow.sh: 111: [: Illegal number: 
workflow OK
rc=0
```

Both deterministic.

### F3. `defaults: run:` in a file that *also* has real bodies is a false failure

Same construct, but where extraction is non-empty the numeric compare works and reports a miscount instead:

```
FAIL: t.yml: extracted 1 run: bodies where the file declares 2
```

`grep -c '^[[:space:]]*run:'` counts a `run:` mapping key; the awk requires a `|`, `&gt;` or a value on the same line. Same for the equally valid

```yaml
        run:
          echo hi
```

Deterministic.

### F4. Block bodies not indented *exactly* two deeper than `run:` are corrupted

`substr($0, ind + 3)` at `tests/workflow.sh:84` hard-codes a 2-space relative indent. YAML only requires the body be *deeper*.

One space deeper — the first character of every line is eaten, producing a false syntax failure on valid YAML:

```yaml
        run: |
         if [ "$x" = y ]; then
           echo yes
         fi
```
```
FAIL: t.yml: run: body 1 is not valid bash
  | ...syntax error near unexpected token `then'
  | `f [ "$x" = y ]; then'
```

Four deeper — two spaces of residual indent survive, which breaks any heredoc terminator:

```
FAIL: t.yml: shellcheck faulted run: body 1
  | SC1039 (error): Remove indentation before end token (or use &lt;&lt;- and indent with tabs).
  | SC1072 (error): Here document was not correctly terminated.
```

Both deterministic. The current `ci.yml` happens to use 2 throughout, so neither shows today.

### F5. `format('{0}-{1}', …)` defeats the expression substitution

`sed 's/\${{[^}]*}}/_GHA_EXPR_/g'` (line 124) stops at the first `}`, so any expression containing a brace — and `format()` is among the most common GHA functions — is left half-substituted:

```yaml
          echo "${{ format('{0}-{1}', github.ref, matrix.os) }}"
```
```
FAIL: t.yml: shellcheck faulted run: body 1
  | SC2296 (error): Parameter expansions can't start with {. Double check syntax.
```

Deterministic. Multi-line `${{ … }}` is likewise unreachable, since `sed` is line-based.

### F6. A `uses:`-only workflow file is a false failure

Adding any ordinary action-only workflow (a labeler, a stale-bot) alongside `ci.yml`:

```
FAIL: labeler.yml: no run: bodies found at all, so nothing was checked
```

The "something must have been checked" invariant is applied per file, where it is only meaningful repo-wide. Deterministic.

### F7. An empty `.github/workflows/` directory passes

`[ -d "$flows" ]` succeeds, both globs fail `[ -f ]` and `continue`, `fails` stays 0:

Same blind-pass class as F2, one level up.

### F8. `_GHA_EXPR_` both silences the real hazard and invents a false one

The classic GitHub Actions script-injection / word-splitting bug is an **unquoted** `${{ }}`. Substituted into a bare word, shellcheck sees a safe literal and says nothing:

```yaml
          echo ${{ github.event.head_commit.message }}
          rm -rf ${{ inputs.path }}/build
```
```
workflow OK
```

Conversely, substituting a constant where the runner has an arbitrary string makes shellcheck reason wrongly in the other direction:

```yaml
          for f in ${{ github.event.head_commit.message }}; do echo "$f"; done
```
```
SC2043 (warning): This loop will only ever run once. Bad quoting or missing glob/expansion?
```

`actionlint` substitutes too, but it also has dedicated expression checks; this has neither. Worth stating in the "what it does not catch" comment at `tests/workflow.sh:12-16`, which currently names only the `timeout(1)` gap.

### F9. Bodies can be silently truncated with the count still agreeing

The `run: |` rule is tested before the `inblock` rule, so a line *inside* a body that matches `^\s*run:\s*[|&gt;]` — a heredoc writing YAML — ends the current body and opens a new one. `grep` counts that line too, so `extracted == declared` and nothing is reported; the tail of the real body is never checked. Likewise a plain-scalar continuation is dropped with no count change, and I confirmed an unterminated quote on such a line passes:

```yaml
        run: cmake --build
          --preset "$UNTERMINATED
```
```
workflow OK
rc=0
```

Deterministic. Both are contrived against today's `ci.yml`; they are the answer to "a body it silently drops".

## Answering the two questions you asked directly

**Is the skip/fail-on-CI logic right?** The idiom matches `tests/tui.sh:61-71` exactly, which is what you designed to. As written the test reds macOS CI (F1).

**Does `-e SC2148` hide anything?** No — and it is also inert. With `-s bash` supplied, shellcheck never emits SC2148 in the first place:

```
$ printf 'echo hi\n' &gt; frag.sh
$ shellcheck -s bash frag.sh          ; # rc=0, silent
$ shellcheck        frag.sh           ; # rc=1, SC2148
```
Removing `-e SC2148` from a copy of the script leaves the real run identical (`workflow OK`). Error codes are unique, so it suppresses nothing else. Harmless, but a reader will take it as load-bearing.
